## API: клиент и сервисы

Компоненты и страницы импортируют только `~~/api/client` и типы из `~~/api/types`,
`api/generated/hbc.ts` напрямую не трогают.

`api/client.ts`:
- `getApi(): ApiServices` → `{ auth, users, listings, applications }`.
  - Клиент: `baseURL = '/api'`, один экземпляр на приложение, таймаут 15 с.
  - Сервер (SSR): новый экземпляр на каждый вызов, `baseURL = apiBaseUrl`,
    `Authorization: Bearer <cookie>`. В mock-режиме SSR ходит в `/api/v1/**` in-process
    (через `$fetch.raw` с пробросом cookie).
  - **На сервере `getApi()` вызывать синхронно в Nuxt-контексте** (начало `setup()`,
    плагин, middleware) — внутри он использует `useRuntimeConfig`/`useCookie`.
- `setUnauthorizedHandler(fn)`: регистрирует `plugins/api.client.ts`. Любой 401 на
  клиенте, кроме `/auth/*`, приводит к: `auth.setUser(null)`, тост «Сессия истекла, войдите
  снова», `navigateTo('/login?redirect=<текущий путь>')`.

`api/types.ts` — «ужесточённые» доменные типы (все поля обязательные, как в protojson
`EmitUnpopulated`; nullable только вложенные сообщения и таймстемпы):
`User`, `Listing` (`myApplication: Application | null`, `stats: ListingStats | null`,
`closedAt: string | null`), `Application` (`decidedAt: string | null`), `ListingSummary`,
`ListingStats`, `ListingsPage {items,total,page,limit}`, `ApiErrorBody {code,message,details}`,
входные `ListingInput`, `ListingUpdateInput` (без `kind`), `ProfileInput`, `LoginInput`,
`RegisterInput`. Enum'ы (строковые значения как в API): `ListingKind`, `ListingStatus`,
`StartupStage`, `ApplicationStatus`.

## Сервер Nitro

- `server/api/auth/{login,register}.post.ts` → `server/utils/backend-auth.ts#proxyAuth`.
  Ходит в бэкенд (или mock), при успехе пишет cookie (`server/utils/auth-cookie.ts`) и
  возвращает `{ user }`. Ошибки — тот же HTTP-статус и `{code, message, details}`.
  `logout.post.ts` удаляет cookie.
- `server/api/[...].ts` — прокси `/api/v1/**` → `${apiBaseUrl}/v1/**` (`proxyRequest`,
  тело потоком в обе стороны, бинарные ответы и `Content-Type`/`Cache-Control` проходят как
  есть, лимита тела нет). Добавляет `Authorization` из cookie, не пробрасывает cookie на бэк.
  Путь берётся из сырого `event.path` и канонизируется `server/utils/proxy-path.ts#canonicalProxyPath`:
  каждый сегмент percent-decode один раз и заново encode, пустые сегменты (`//`, завершающий `/`)
  выбрасываются, `.`/`..`, закодированный `/` и битый `%` → 404. Проксируется только `/v1/**`,
  всё поддерево `/v1/auth/**` → 404 `{code:5}`. На бэк уходит канонический путь.
  Бэк недоступен → 502 `{code:14}`.
- Флаг `Secure` у cookie **по умолчанию выключен** (решение координатора: compose открывает фронт
  по `http://localhost:3000`, Safari не сохраняет Secure-cookie на HTTP). За HTTPS-прокси —
  `NUXT_COOKIE_SECURE=true`.

## Auth

- `stores/auth.ts` — `useAuthStore()`: `user: Ref<User|null>`, `isAuthenticated`,
  `setUser(user|null)`, `fetchMe()` (null на 401), `login(input)`, `register(input)`,
  `logout()`. Обновили профиль или фото (F5) — вызвать `setUser(newUser)`.
- **Соглашение:** `login`, `register`, `logout` и обработчик истёкшей сессии вызывают
  `clearNuxtData()` — кэш `useAsyncData`/payload не переживает смену пользователя. Не держите
  пользовательские данные в модульных переменных или `useState` — их пришлось бы чистить отдельно.
- `plugins/auth.server.ts` — `fetchMe` на SSR, если есть cookie; на 401 cookie удаляется.
- `middleware/auth.global.ts` — публичные только `/login`, `/register`. Без пользователя →
  `/login?redirect=<fullPath>`; с пользователем на публичных → `safeRedirect(query.redirect)`
  (`~/utils/redirect`: только same-origin пути).
- `composables/useApplicationsBadge.ts` → `Ref<number>`, в F0 `ref(0)`; **F4 реализует**
  (бейдж на пункте «Отклики» в header и tab-bar уже читает его).

## Соглашения для страниц F1–F5

```tsx
import { defineComponent } from 'vue';
import { getApi } from '~~/api/client';
import { PageHeader } from '~/components/ui/page-header';
import { ErrorState } from '~/components/states/error-state';

export default defineComponent({
  name: 'ListingPage',
  setup() {
    const api = getApi();                       // синхронно, в начале setup
    const route = useRoute();
    const id = computed(() => String(route.params.id));
    const { data, error, status, refresh } = useAsyncData(
      () => `listing:${id.value}`,
      () => api.listings.get(id.value),
    );
    // 404 от API → страница ошибки:
    // if (getErrorStatus(error.value) === 404) throw createError({ statusCode: 404, fatal: true });
    return () => /* Skeleton при status==='pending', ErrorState при error, иначе контент */;
  },
});
```

- Данные: `useAsyncData` + `getApi()`. SSR получает данные с cookie пользователя, клиент
  гидрируется без повторного запроса. Ключи уникальные (`'feed:…'`, `'listing:<id>'`).
- Мутации: `try { await api.applications.accept(id) } catch (e) { toast.error(getErrorMessage(e)) }`
  (`toast` из `vue-sonner`, `<Toaster>` уже в `app.tsx`). Повторные действия — блокировать
  кнопку через `loading`.
- Компоненты: TSX, `defineComponent((props: Props, ctx) => () => …, { props, name })`,
  `prop<T>()` из `@fe/prop-types`, `index.module.css` рядом. Строки в JSX — `{'Текст'}`.
  stylelint требует алфавитного порядка свойств, длинные значения — в одну строку.
