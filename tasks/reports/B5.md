## Отклонения от SPEC, найденные e2e, и как исправлены

1. **Неизвестное имя enum в теле молча превращалось в UNSPECIFIED.** Пример:
   `"stage":"MVP"` → «Стадия: укажите стадию» вместо «Некорректный формат запроса». Причина —
   `DiscardUnknown` (ARCHITECTURE §3): protojson с ним отбрасывает и неизвестные имена enum.
   Исправлено так: `requestMarshaler` до декодирования сверяет строковые значения enum-полей
   с дескриптором запроса (рекурсивно, списки тоже). Неизвестные *поля* по-прежнему
   игнорируются.
2. **Ошибки разбора тела и query отдавали английский текст protojson/strconv.** Исправлено:
   ошибка декодера заменяется на `badRequestError` с текстом «Некорректный формат запроса»,
   а `runtime.SetQueryParameterParser` оборачивает `DefaultQueryParser`. Пустое тело (EOF)
   ошибкой не считается.
3. **`?query=%zz` (битый escape) давал английский текст `url.ParseQuery`.** Исправлено
   middleware `rejectBadQuery` перед gateway.
4. **`WWW-Authenticate` с кириллицей** — см. доработку 2.

## Замечания для фронта (F6, I1)

**Формат.**
- Все поля присутствуют всегда: `""`, `[]`, `false`, `0`; вложенные сообщения и неустановленные timestamps — `null`.
- Enum — строки (`LISTING_KIND_STARTUP`, `APPLICATION_STATUS_PENDING`). У вакансии `stage = "STARTUP_STAGE_UNSPECIFIED"`, у стартапа `compensation = ""`.
- Timestamps — RFC 3339 UTC **с микросекундами**: `"2026-10-19T23:03:28.909982Z"`, а не как в примере SPEC без дробной части. `new Date()` это парсит; при сравнении строк не рассчитывать на фиксированную длину.
- `stats` — только у своих публикаций (у своей без откликов — нули), у чужих `null`.
- `myApplication` — только у чужих публикаций, отозванный отклик не показывается (после withdraw — `null`).
- `isMine` — bool.
- `closedAt` — `null` у активных; повторный close возвращает тот же `closedAt`.
- `avatarUrl` — `""` или `/v1/avatars/<uuid>.jpg`; при каждой загрузке имя новое, старый URL сразу даёт 404.

**Ошибки** — `{code, message, details: []}`, показывать `message`. Тексты подтверждены e2e:

| Ситуация | HTTP / code | message |
|---|---|---|
| нет токена или токен невалидный/просрочен | 401 / 16 | «Требуется вход» |
| login: неверный пароль, нет пользователя, некорректный логин | 401 / 16 | «Неверный логин или пароль» |
| логин занят (без учёта регистра) | 409 / 6 | «Логин уже занят» |
| повторный отклик | 409 / 6 | «Вы уже откликались на эту публикацию» |
| своя / закрытая публикация | 400 / 9 | «Нельзя откликнуться на свою публикацию» / «Публикация закрыта» |
| update закрытой | 400 / 9 | «Публикация закрыта» |
| переход из финального статуса | 400 / 9 | «Решение по отклику уже принято» |
| чужое действие (публикация, отклики на неё, другая сторона отклика) | 403 / 7 | «Недостаточно прав» |
| не найдено, в том числе не-uuid в пути | 404 / 5 | «Публикация не найдена» / «Отклик не найден» / «Участник не найден» / «Фото не найдено» |
| разбор запроса | 400 / 3 | «Некорректный формат запроса» |
| ошибки валидации | 400 / 3 | «Название: от 3 до 120 символов», «Описание: от 10 до 5000 символов», «Стадия: укажите стадию», «Стадия: только для стартапа», «Условия: только для вакансии», «Вид публикации: выберите стартап или вакансию», «Теги: без повторов», «Размер страницы: от 1 до 50», «Страница: не меньше 1», «Поиск: не больше 100 символов», «Сообщение: от 1 до 2000 символов», «Пароль: от 8 до 72 символов», «Логин: от 3 до 32 символов, латиница, цифры и _», «Навыки: без повторов», «Имя: от 1 до 80 символов», «Кратко о себе: не больше 120 символов», «Фото: поддерживаются JPEG, PNG и WebP», «Фото: минимум 64×64», «Фото: файл пустой» (пустой `data`, BFF) |
| сервер | 500 / 13 | «Внутренняя ошибка» |

**Поведение.**
- Разбор запроса: так отвечают невалидный JSON, неверный тип поля, неизвестное имя enum в теле или query, `page=abc`, битый escape в query. Неизвестные поля тела игнорируются.
- `page=0` / `limit=0` (или не переданы) → 1 / 20; в ответе ленты приходят применённые `page` и `limit`.
- `accept` / `decline` / `withdraw` / `close` принимают пустое тело или `{}` (TS-клиент из swagger шлёт `body`).
- Все строки на сервере обрезаются (trim). Логин приводится к lower-case. У telegram отбрасывается ведущий `@`. Пустые теги и навыки отбрасываются.
- Аватар: тело `{data: base64}`. Ответ `GET /v1/avatars/…` — `image/jpeg`, `Cache-Control: public, max-age=31536000, immutable`, без токена.
- Демо: `anna` / `boris` / `vera` / `dmitry`, пароль `demo1234`. В ленте 5 публикаций, №6 «Frontend-разработчик в Volunteer Hub» закрыта. UUID при каждом сиде новые — ссылаться только по `username` / `title`.

## Дыры и вопросы к документам

1. **ARCHITECTURE §3 и SPEC §2.4.** `DiscardUnknown` в ARCHITECTURE несовместим с требованием
   SPEC «неизвестный enum → 400» без доработки: protojson отбрасывает и неизвестные имена
   enum. Решено проверкой имён enum до декодирования (отклонение 1). Стоит дописать в
   ARCHITECTURE §3 одной фразой.
2. **SPEC §6 не задаёт `description` публикаций и `about` пользователей.** Тексты придуманы
   (`internal/seed/data.go`), стабильные ключи — `username` и `title`, как в SPEC.
3. **Проверка «users пуста» для сида.** Порта для неё нет, поэтому `internal/seed` делает
   `SELECT EXISTS … FROM users.users` напрямую (только чтение, плюс advisory lock). Это
   единственное место вне контекста `users`, которое знает его таблицу. Альтернатива —
   метод порта `users.Service.Count/Any`, но сигнатуры порта менять было нельзя.
4. **Пример в SPEC §4.3 показывает timestamps без дробной части,** фактически приходят
   микросекунды (RFC 3339 это допускает).
5. **`make test-integration` / `test-e2e` / `test-all` в конце делают `down -v`,** то есть гасят
   и инфраструктуру, поднятую `make test-env-up`. Для своей инфраструктуры — `TEST_ENV=external`.
   Задокументировано в README.
