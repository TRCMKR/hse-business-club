# Отчёт F5 — Профиль, публичный профиль, страница ошибки

Ветка `task/F5`. Пути ниже указаны относительно `front/`.

## Что сделано

- `app/pages/me/index.tsx`. Собственный профиль: `ProfileCard`, в слоте аватара `AvatarEditor`,
  кнопка «Редактировать» открывает inline-форму `ProfileForm` на месте карточки.
  «Выйти» (с `loading`) вызывает `auth.logout()` и переходит на `/login`; кнопка в шапке страницы
  сохранена, на мобильном это единственный способ выйти.
- `app/pages/users/[id].tsx`. Публичный профиль: `useAsyncData('user:<id>')`, та же
  `ProfileCard` без редактирования, skeleton на время загрузки. 404 или id не в формате UUID
  (в этом случае запрос не делается) → EmptyState «Участник не найден» с кнопкой «В ленту».
  Прочие ошибки → `ErrorState` с «Повторить».
- `app/error.tsx` выводится внутри `NuxtLayout name="default"` (header, tab-bar).
  404: «Страница не найдена» и «В ленту» (`clearError({ redirect: '/' })`).
  Прочие ошибки: «Что-то пошло не так», «Повторить» (`location.reload()`) и «В ленту».
- Тесты: 4 новых файла, 22 теста. Итого 16 файлов, 178 тестов.

## Компоненты (`app/components/profile/`)

| Компонент | Props | Emits | Slots |
|---|---|---|---|
| `ProfileCard` (`profile-card`) | `user: User` | — | `avatar` (заменяет `Avatar` 112px), `actions` (кнопки под именем) |
| `ProfileForm` (`profile-form`) | `user: User` (начальные значения) | `saved(user)`, `cancel` | — |
| `AvatarEditor` (`avatar-editor`) | `user: User`, `size` (112, 24–128) | `updated(user)` | — |

- `ProfileCard` показывает аватар, имя, `@username`, headline, ссылку «Telegram: @handle» →
  `https://t.me/<handle>` (`target=_blank`, `rel=noopener noreferrer`), а также секции «О себе»
  (`pre-line`) и «Навыки» (чипы). Пустые поля и секции не рендерятся. До 560px карточка
  выстраивается в колонку по центру.
- `ProfileForm` работает на vee-validate с `profileFormSchema` из `utils/validation.ts`. Поля:
  Имя, Кратко о себе, О себе (счётчик 2000), Навыки (`ChipsInput`, max 20, длина 40), Telegram.
  «Сохранить» с `loading` вызывает `users.updateMe`, затем `auth.setUser`, показывает тост
  «Профиль сохранён» и эмитит `saved`. Серверная ошибка выводится над кнопками (`role=alert`).
- `AvatarEditor`: файл выбирается кликом по аватару (оверлей с камерой) или кнопкой «Загрузить фото»
  («Заменить фото», если фото уже есть). Скрытый `<input type=file accept="image/jpeg,image/png,image/webp">`
  без `capture`. Проверка на клиенте выполняется в `avatar-editor/validate.ts#validateAvatarFile`:
  MIME-тип, при пустом типе — расширение, размер ≤ 5 МиБ. Тексты ошибок дословно из SPEC §2.3, показ — toast.
  После выбора показывается превью через `URL.createObjectURL` с кнопками «Сохранить» (`loading`) и «Отмена»;
  URL освобождается при отмене, после загрузки и при unmount. Ответ `User` уходит в `auth.setUser`,
  поэтому header и карточка обновляются сразу. При ошибке 400 показывается toast с `message`, превью остаётся.
  «Удалить фото» → `ConfirmDialog` (danger) → `users.deleteAvatar()` → `setUser`.

## Как проверял

| Критерий | Проверка |
|---|---|
| `npm run lint`, `npm run test`, `npm run build` | зелёные (178/178) |
| Редактирование сохраняется и видно в header | Запрос `PUT /api/v1/me` на mock (prod-сборка, `NUXT_MOCK_API=true`, порт 3105) вернул новое имя, SSR `/me` выдал header с `title="Анна Тест"`. Дубль навыков `Go`/`go` → 400 «Навыки: без повторов». Обновление стора после сохранения покрыто тестом `ProfileForm`. Header берёт `auth.user` реактивно. |
| Фото: загрузка, удаление | `POST /api/v1/me/avatar` с PNG 80×80 вернул `avatarUrl`, SSR `/me` выдал `<img src="/api/v1/avatars/<uuid>.jpg">`. После `DELETE` пришёл `avatarUrl: ""` (снова сгенерированный аватар). GIF → 400 «Фото: поддерживаются JPEG, PNG и WebP». Тесты `AvatarEditor`: файлы 6 МБ и `.gif` отклоняются без вызова сервиса, после загрузки обновляется `auth.user.avatarUrl`; также покрыты удаление с подтверждением, отмена превью и ошибка 400. |
| `/users/<несуществующий uuid>` | SSR показывает «Участник не найден» и для несуществующего UUID, и для `/users/abc`. |
| `/listings/<не uuid>` → 404 | **Не выполнен в F5:** `/listings/:id` пока заглушка F0 и отвечает 200. Нужно проверить после merge F2. Сама страница ошибки проверена на `/nonexistent`: SSR отдаёт 404, «Страница не найдена» и «В ленту» внутри default layout. |

Проверить руками в браузере (клик, превью, live-обновление header) не удалось: Chrome-расширение
в сессии недоступно. Клиентское поведение покрыто компонентными тестами (jsdom).
Вместо `npm run dev` использовал prod-сборку с mock (`node .output/server/index.mjs`): места на
диске почти нет, а Vite-кэш dev-режима занял бы ещё.

## Правки вне зоны

- `server/mock/routes.ts`: текст 404 для участника «Пользователь не найден» заменён на
  «Участник не найден» (SPEC §2.3, DECISIONS 01:45). Страница показывает свой текст, это правка
  ради консистентности mock.
- `app/pages/me/index.module.css` (стиль заглушки F0) удалён: страница его больше не использует.
- Новый `app/pages/users/[id].module.css` лежит рядом со страницей из зоны владения.

## Не сделано / ограничения

- Критерий `/listings/<не uuid>` зависит от F2.
- Ручная проверка в браузере не проводилась (см. выше).
- Нет кропа и ресайза на клиенте: сервер сам центрирует и уменьшает до 512×512. Ограничение
  ≥ 64×64 и ≤ 8000×8000 проверяет только сервер, ответ показывается тостом.

## Дыры в документах

- Mock F0 расходился со SPEC в тексте NotFound для участника. В mock исправлено.
- В SPEC не сказано, что отдавать на `GET /v1/users/{id}` с id не в формате UUID: 400 или 404.
  Фронт не делает запрос и сразу показывает «не найден».
