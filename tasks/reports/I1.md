# Отчёт I1 — smoke-тест и сквозная проверка

Ветка `task/I1`. Сделано всё из задания, включая оба раздела «Дополнения координатора» (ревью B5 и F6).
Ручной чек-лист проходил субагент через headless Chrome (playwright-core), на 375 и 1280. Сам он
файлов в репозитории не менял. Smoke, правки и наблюдаемость делал координатор.

## Итог

- `scripts/smoke.sh` + `make smoke`. Скрипт проходит основной сценарий через API, загружает фото и
  получает его из MinIO, логинится через фронт (httpOnly-cookie, прокси Nitro). 16 проверок.
- Цепочка `make reset && make up && make smoke` зелёная, но проверена **через override портов**
  (см. «Окружение»).
- Корневые `make lint` и `make test` зелёные: бэк — unit, integration и e2e с `-race`; фронт — 35
  файлов, 317 тестов. После двух последних коммитов (EXIF, подсказки полей) отдельно перепрогнаны
  `make lint` и `go test -race ./...` в `back/`, а также `npm run lint && npm run test` во фронте.
- Ручной чек-лист: 8 пунктов (58 проверок на каждой ширине) — PASS на 375 и на 1280. Нашлись два бага, оба
  исправлены здесь: EXIF-ориентация фото и дубль «ошибка + подсказка» под полями.
- Наблюдаемость (`make obs`): в Jaeger есть трейс `GET /v1/listings` → gRPC → SQL; в Prometheus
  есть `grpc_server_handled_total` и `http_request_duration_seconds`.

## Окружение: порты заняты

На машине разработчика порты 8080–8082 заняты посторонним процессом, поэтому `make up` с портами
по умолчанию не поднимается. Все проверки шли с override-файлом вне репозитория (он не
закоммичен), проект `hbc-i1`:

```yaml
# i1-ports.override.yaml
services:
  back:
    environment:
      CORS_ORIGINS: http://localhost:13000
    ports: !override
      - "18080:8080"
      - "18081:8081"
  front:
    ports: !override
      - "13000:3000"
```

```sh
export COMPOSE_PROJECT_NAME=hbc-i1
make reset COMPOSE_FILES=/abs/path/i1-ports.override.yaml
make up    COMPOSE_FILES=/abs/path/i1-ports.override.yaml
make smoke API_URL=http://localhost:18080 FRONT_URL=http://localhost:13000
make obs   COMPOSE_FILES=/abs/path/i1-ports.override.yaml   # Jaeger :16686, Prometheus :9090 — свободны
```

Первая сборка один раз упала на `Head registry-1.docker.io … EOF` (сеть, как у I0), повтор прошёл.
После проверок выполнены `docker compose -p hbc-i1 --profile observability down -v` и
`docker rmi hbc-back:local hbc-front:local`. `prune` не запускался.

## Smoke (`scripts/smoke.sh`, `make smoke`)

Нужны bash (подходит и системный 3.2 на macOS), curl и jq. Параметры:
- `API_URL` — по умолчанию `http://localhost:8080`;
- `FRONT_URL` — по умолчанию `http://localhost:3000`, пустое значение пропускает проверку фронта;
- `PASSWORD` — по умолчанию `demo1234`.

В корневом `Makefile` добавлены переменные `API_URL`, `FRONT_URL` и `COMPOSE_FILES` (дополнительные
`-f` для compose); `make up`, `down`, `reset` и остальные цели их учитывают.

Шаги:
1. `/v1/ping`, `/readyz` (`db` и `blob` = ok);
2. вход Анны;
3. Анна создаёт стартап с уникальным заголовком: active, `isMine`, `stats.total = 0`;
4. вход Бориса;
5. лента Бориса (`kind` + `query`) содержит стартап: `isMine=false`, `myApplication=null`, `stats=null`;
6. отклик → PENDING;
7. повторный отклик → 409 «Вы уже откликались на эту публикацию»;
8. во входящих Анны есть отклик Бориса в статусе PENDING;
9. accept → ACCEPTED, `decidedAt` заполнен;
10. в отправленных Бориса отклик ACCEPTED;
11. `GET /v1/listings/{id}` от Бориса → `myApplication.status = ACCEPTED`;
12. Борис загружает фото → `avatarUrl` вида `/v1/avatars/*.jpg`;
13. `GET avatarUrl` → 200, `Content-Type: image/jpeg`, тело начинается с `FF D8`;
14. уборка: фото удалено, старый URL → 404;
15. уборка: публикация закрыта, чтобы повторные прогоны не засоряли ленту;
16. фронт: `POST /api/auth/login` → 200, `Set-Cookie: hbc_token…HttpOnly`, токена в теле нет;
    `GET /api/v1/me` с cookie → boris.

Скрипт можно запускать повторно на том же стеке. Проверено: два прогона подряд проходят.

**Отклонение от задания:** в скрипт зашит PNG **64×64** (135 байт), а не 1×1. Сервер отклоняет фото
меньше 64×64 («Фото: минимум 64×64», SPEC §2.4), так что 1×1 дал бы 400.

Ошибки выводятся по-русски, код возврата ненулевой. Примеры:

```
 1. API отвечает (GET /v1/ping, /readyz) ...   ОШИБКА: API http://localhost:18099 не отвечает на GET /v1/ping: curl: (7) Failed to connect … Стек поднят (make up)? Другой адрес — API_URL=...
 2. вход Анны (anna) ...   ОШИБКА: ожидался HTTP 200, получен 401 (POST /v1/auth/login)
  ответ: {"code":16,"message":"Неверный логин или пароль","details":[]}
```

Финальный прогон после `make reset && make up` (override):


Использовалась prod-сборка фронта из compose (`:13000`). Ширина 375×812 — с DPR 2, isMobile и
hasTouch; ширина 1280×800. Скриншоты по каждому пункту лежат в scratchpad сессии (`i1qa/shots/`), в
репозиторий не добавлены (актуальные скриншоты экранов — `docs/screenshots/` из F6).

Запрос `GET /v1/listings?kind=LISTING_KIND_STARTUP` от Анны. В Jaeger (`/api/traces`, сервис
`hbc-back`) пришёл трейс `e18387bc…` из 19 спанов. Пути от корня:

```
GET /v1/listings → hbc.v1.HseBusinessClub/V1ListListings → hbc.v1.HseBusinessClub/V1ListListings → BEGIN
GET /v1/listings → hbc.v1.HseBusinessClub/V1ListListings → hbc.v1.HseBusinessClub/V1ListListings → SELECT
GET /v1/listings → hbc.v1.HseBusinessClub/V1ListListings → hbc.v1.HseBusinessClub/V1ListListings → SELECT → SELECT
GET /v1/listings → hbc.v1.HseBusinessClub/V1ListListings → hbc.v1.HseBusinessClub/V1ListListings → COMMIT
```

Цепочка: HTTP-спан gateway → клиентский и серверный gRPC-спаны (`otelgrpc`) → спаны pgx (SQL).

## Что не сделано / ограничения

- Критерий `make reset && make up && make smoke` проверен только через override портов. На портах
  по умолчанию (8080/8081/3000) не прогонялся: они заняты на машине разработчика.
- 503 → навигация из нижней панели: проверено unit-тестом, на живом стеке не прогонялось.
- Возможное расхождение относительных дат между SSR и гидрацией (ограничение F2/F6) не трогал.
- Предупреждение h3 про `statusMessage` (F6) не трогал.
- EXIF: применяется только ориентация из IFD0 JPEG. Для WebP/PNG EXIF не читается — у них на практике
  так не бывает.

## Для README (I2)

- **Адреса (по умолчанию):** фронт `http://localhost:3000`; API `http://localhost:8080`; debug
  `http://localhost:8081` (Swagger UI `/docs/`, `/metrics`, pprof). С `make obs` — Jaeger
  `http://localhost:16686`, Prometheus `http://localhost:9090`, консоль MinIO `http://localhost:9001`.
- **Команды:** `make up` → `make smoke` → открыть фронт, войти как `anna` / `demo1234` (также
  `boris`, `vera`, `dmitry`). `make reset` стирает БД и фото. `make obs` — трейсы и метрики.
  `make lint`, `make test` — тесты бэка поднимают своё окружение на 5433/9000.
- **Если порты заняты:** override-файл с `ports: !override` и `CORS_ORIGINS` (пример выше), затем
  `make up COMPOSE_FILES=…` и `make smoke API_URL=… FRONT_URL=…`. Также работают `COMPOSE_FILE` и
  `COMPOSE_PROJECT_NAME` из окружения.
- **Известные ограничения:**
  - сеть Docker Hub иногда рвётся при первой сборке (`… EOF`) — повторить `make up`;
  - при ошибке сид откатывается, а если не удался и откат — `make reset`;
  - фото ≤ 5 МБ, ≥ 64×64, на выходе 512×512 JPEG; EXIF-ориентация JPEG учитывается, остальные
    метаданные удаляются;
  - cookie без `Secure` по умолчанию (HTTP на localhost), за HTTPS — `NUXT_COOKIE_SECURE=true`;
  - UUID сида меняются при каждом `make reset`;
  - smoke оставляет в базе закрытые публикации «Smoke … — стартап для проверки» (по одной на прогон).
- **Отклонения:** smoke использует PNG 64×64, а не 1×1 (минимальный размер фото).
