### Тема, токены, a11y UI-кита (субагент B, п. 13 и п. 3–4)

**Токены и шрифт**
- `--font-family`: добавлен `'Montserrat Fallback: Arial'`. Имя сверено с `@font-face`, который генерирует `@nuxt/fonts`.
- `theme-color`: два meta с `media` — `#f4f6fb` для светлой темы и `#06081c` для тёмной.

- README «Дизайн и токены» приведён к факту. `grep 'rgb(\|#hex\|font-size: N'` по модулям ничего не находит.

**Тёмная тема**
- Активный чип фильтра на `/me/applications` получил кольцо `--color-chip-selected-ring` и полужирный шрифт.
- Navy-полоса на `/login` и `/register` теперь своего оттенка `#0b1030`, с границей и тенью.
- Тосты `vue-sonner` в тёмной теме были светлыми — их переменные сопоставлены с токенами.
- Диалог в тёмной теме сливался с затемнением — добавлена граница.

**Поведение и отступы**
- `prefers-reduced-motion`: skeleton больше не мерцает за 0.01ms. Вместо этого — медленная пульсация прозрачности 2.4s.

**Контраст и фокус**
- Рамка полей `--color-border-strong`: в светлой теме было 1.60:1, стало 3.34:1; в тёмной — 1.76:1 → 3.22:1. WCAG 1.4.11 выполнен.

**a11y**
- Счётчик откликов в навигации был `span` с `aria-label`, но без роли. Теперь цифра `aria-hidden`, а текст «, новых: N» лежит в `visually-hidden`.

## Живой бэкенд: основной сценарий

Стек поднимался через `docker compose -p hbc-f6` с override портов: back на 18080, фронт на 13000. Override вне репозитория, не коммитился. Скрипт Playwright в scratchpad проходит сценарий через UI:

1. вход Анны кнопкой «Войти как Анна»;
2. Анна создаёт стартап, стадия MVP;
3. Борис находит его поиском в ленте и откликается — статус «Ожидает»;
4. Анна принимает отклик на `/listings/:id/applications`;
5. Борис видит «Принят» на `/me/applications`.

| Ширина | dev-сборка | prod-сборка |
|---|---|---|
| 375 | OK | OK |
| 1280 | OK | OK |

Дополнительно на живом стеке:
- загрузка фото через Nitro-прокси → `image/jpeg` с `Cache-Control: public, max-age=31536000, immutable`; после удаления — 404.
- Двойных запросов при SSR нет: после гидрации на всех 10 экранах клиент делает ровно один запрос — бейдж `received?status=PENDING`, он client-only по дизайну F4. Ввод 14 символов в поиск дал 1 запрос (debounce). 3 переключения вида — 2 запроса, третий взят из кэша.
- Hydration mismatch на prod-сборке: прогон по 5 страницам × 2 ширины (`/`, `/me`, `/me/listings`, `/me/applications` и её вкладка «Полученные») — чисто. Аватары (`BlobAvatar`) в SSR и после гидрации совпадают; `TODO(F7)` в `ui/avatar` не осталось, заглушки нет.

## Баги бэкенда для I1

1. **`GET /v1/listings?kind=` (пустое значение enum в query) → 400 «Некорректный формат запроса».** Ожидается, что пустой параметр равен отсутствующему (`UNSPECIFIED`), как `?query=`. То же для `?status=` в `/v1/me/applications/*`. Фронт пустые значения не шлёт (`cleanQuery`), поэтому пользователь этого не видит. Это несоответствие поведения для прямых клиентов API. Низкий приоритет.

Других расхождений с контрактом и SPEC §2.3/§4.2 на живом стеке не найдено:
- тексты 400/403/404/409 совпадают с таблицей B5;
- timestamps с микросекундами парсятся;
- `stats` и `myApplication` приходят по правилам B5.

## Что не сделано / ограничения

- **Относительные даты** («только что» и т.п.) не обёрнуты в `<ClientOnly>`. Если SSR и гидрация приходятся на разные минуты, Vue пишет «Hydration completed but contains mismatches». Это ограничение F2: за весь прогон поймано один раз, повторить не удалось.
- **`createError({ statusMessage: 'Публикация не найдена' })`.** h3 пишет в лог сервера предупреждение «prefer `message` … `statusMessage` will be sanitized». Сейчас кириллица в `statusMessage` доходит до клиента; на это опираются `error.tsx` и e2e. Если обновление h3 начнёт её вырезать, `error.tsx` покажет общий заголовок «Страница не найдена» — страница не сломается.
- **Двойной запрос на `/me/applications?tab=received&status=pending`.** Бейдж в навигации запрашивает тот же список, что и страница. Это два независимых потребителя; бейдж client-only и ходит в API не чаще раза в 30 с.
- **Тема.** Переключателя темы и интеграции с темой Telegram (`themeParams`) нет. Работает только `prefers-color-scheme`, как в F8.
- **Профиль** проверен только через API и unit-тесты: загрузка фото через UI на живом стеке не прогонялась. API-путь через Nitro-прокси и MinIO на живом стеке проверен.
