## Как устроено

**URL — единственный источник фильтров.** `/?kind=LISTING_KIND_STARTUP&q=FinTrack`.
Значения по умолчанию в URL не пишутся: `/` — это «Все» без поиска. Неизвестный `kind`
считается «Все». `q` обрезается по краям и до 100 символов (`LIMITS.query.max`, SPEC §2.4).
Посторонние параметры (`utm` и т. п.) сохраняются. Запись в URL — через `router.replace`:
набор текста не засоряет историю.

**Поиск.** Значение в поле живёт отдельно от URL: в URL оно попадает через 300 мс после
последнего ввода, по Enter или сразу при очистке. Внешняя смена URL (кнопка «Сбросить
фильтры», «назад») обновляет поле. Пробел, который пользователь ещё набирает в конце
строки, при этом не стирается.

**Пагинация.** Ключ `useAsyncData` — `feed:<kind>:<limit>:<q>`. При смене ключа Nuxt
загружает первую страницу заново, а `useFeed` сбрасывает догруженные страницы и номер
страницы на 1. Ответ «Показать ещё», пришедший уже после смены фильтров, отбрасывается
(счётчик поколений). Дубли по `id` при сдвиге страниц (кто-то опубликовал новое)
отфильтровываются. `hasMore = items < total`; если сервер вернул пустую страницу раньше
`total`, догрузка останавливается. Размер страницы — 20 (умолчание API).

**Состояния.** Первая страница грузится (в том числе после смены фильтра) → 3 скелетона. «Показать ещё» → `loading` на
кнопке. Пусто без фильтров → «Пока нет предложений» + «Создать публикацию»
(`/listings/new`). Пусто с фильтрами → «Ничего не нашлось» + «Сбросить фильтры».
Ошибка первой страницы → `ErrorState` с «Повторить» (`refresh`). Ошибка «Показать ещё»
→ тост, загруженные карточки остаются.

**Раскладка.** Сетка в 1 колонку, от 1024px — в 2. Фильтры на телефоне идут столбиком,
от 768px — в строку. FAB «Создать» на мобильном уже есть в `layouts/default.tsx` (F0),
его не трогал.

## Отклонения и решения

- Плейсхолдер поиска — «Поиск по названию и описанию»: так ищет API (SPEC §1, `ILIKE` по
  title/description). Теги в поиск не входят.
- «Это всё» показывается под любым непустым списком, когда догружать больше нечего, в том
  числе если всё поместилось на первой странице.
- Синхронизацию с URL держит `FeedFilters`, а не страница. Так тест «debounce, URL» из
  задания проверяет сам компонент. Страница только читает `route.query`.

## Доработка по ревью (итерация 1)

**Проблема.** При смене ключа `useAsyncData` Nuxt 4 держит в `data` ответ прежнего ключа,
пока новый запрос в `pending`. `loading` требовал `!data`, поэтому при смене фильтра на
экране оставались карточки старого фильтра без скелетонов. `hasMore` и `total` тоже
считались по старой странице, и «Показать ещё» в этот момент дописывало страницу 2
нового фильтра к странице 1 старого.

**Исправление** (`front/app/composables/useFeed.ts`):
- первая страница берётся из `data` только при `status === 'success'` (`headPage`). Пока
  новый ключ в `pending`, `items = []`, `total = 0`, `hasMore = false`;
- `loading = status ∈ {pending, idle}`. Скелетоны показываются при первой загрузке, при
  смене фильтра и при повторе;
- `loadMore` при `hasMore = false` ничего не делает, так что догрузка во время `pending`
  невозможна.

**Тест.** В `front/tests/feed-use-feed.test.ts` добавлен сценарий: смена фильтра при
придержанном ответе → `loading = true`, `items = []`, `total = 0`, `hasMore = false`,
`loadMore()` не делает запроса. После ответа — новые карточки, страница 1.

**Проверка в браузере.** Prod-сборка с mock, headless Chrome. Ответ на
`kind=LISTING_KIND_VACANCY` придержан через CDP `Fetch`. Во время ожидания: URL
`?kind=LISTING_KIND_VACANCY`, 0 карточек, 3 скелетона, кнопки «Показать ещё» нет. После
ответа — 2 вакансии.

Из «Дыр» убран пункт про `q=Go`: критерий в main заменён на `q=FinTrack`.

`npm run lint`, `npm run test` (184/184) и `npm run build` — зелёные.
