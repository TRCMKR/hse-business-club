## Решения и неоднозначности

1. **Невалидный uuid в пути → `NotFound`** с текстом сущности («Участник не найден»,
   «Публикация не найдена», «Отклик не найден»), порты не вызываются. Такой id не может
   указывать на объект, и ответ не отличается от «не существует». Все id в контракте — параметры
   пути, поэтому случая «uuid в теле → InvalidArgument» нет.
2. **Enum вне контракта** (возможно только числом в JSON или по gRPC — имена проверяет gateway):
   `kind` при создании → «Вид публикации: выберите стартап или вакансию» (то же, что для
   UNSPECIFIED); остальные (`stage`, фильтры `kind`/`status`) → `InvalidArgument` «Некорректный
   формат запроса», тот же текст, что у gateway для неизвестного имени enum (SPEC §2.4).
   В DECISIONS 01:45 для неизвестного фильтра статуса отклика указан текст контекста «Статус
   отклика: неизвестное значение», но до контекста такое значение не дойдёт: BFF отсекает его
   на маппинге. Если нужен именно этот текст — поменять одну строку в `appStatusFilter`.
3. **page/limit.** 0 → 1/20, остальные значения (отрицательные, > 50) передаются в контекст
   как есть, валидирует `ListActive` (решение 01:35). В ответе `page`/`limit` берутся из `Page`
   контекста.
4. **`stage` UNSPECIFIED → `""`**; обязательность для startup и запрет для vacancy проверяет
   контекст.
5. **`myApplication`** ищется только для чужих публикаций (на свою откликнуться нельзя), `stats` —
   только для своих. `myApplication.listing` — summary этой же публикации, `applicant` — текущий
   пользователь (берётся из того же батча `Users.GetMany`, поэтому лишнего вызова нет).
6. **Нет публикации или участника в ответе батча** (при целостных данных такого не бывает) →
   соответствующее поле `null`, а не ошибка: список не падает из-за одной битой ссылки.
7. **Пустые списки** — пустой slice (protojson всё равно отдаёт `[]`).
8. **`grpc.SetHeader` для `V1GetAvatar`.** Если вызов вернул ошибку (без gRPC-стрима, то есть
   только в прямом вызове из теста), ответ — `Internal`. В unit-тесте контекст снабжается
   фейковым `ServerTransportStream`, а заголовок проверяется и через реальный gateway.
9. **Сообщения 403** в фейках («Редактировать публикацию может только автор», «Смотреть отклики
   может только автор») — условные: настоящий текст задают контексты, BFF его не меняет.

## Правки вне зоны

- `back/internal/platform/server/server_test.go`: тесты B0 ждали 501 от заглушек BFF
  (`/v1/me`, `/v1/avatars/x.jpg`) и создавали `bff.New` без портов, поэтому после B4 падали
  с 500 (nil-порт → panic → recovery). Вместо BFF подключил локальный `stubService` (только
  `V1Ping`, остальное — `Unimplemented`), с теми же `PublicMethods`/`SwaggerJSON`. Так тесты сервера
  не зависят от BFF. Проверки тестов не менялись.
- Слил `main` (решения DECISIONS 01:45). Конфликты в `tasks/STATUS.md` и
  `tasks/B5-assembly-seed-e2e.md` решены в пользу версии `main`: это файлы координатора.

Контракт (`hbc.proto`), порты и ARCHITECTURE/SPEC не менял.
