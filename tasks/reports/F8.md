# Отчёт F8 — Визуальный стиль в духе сайта Бизнес-клуба

Ветка `task/F8`. Пути — относительно `front/`, если не указано иное.

## Итог

Интерфейс «переодет» через токены `app/assets/css/main.css`: navy-навигация (header на
десктопе, tab-bar на мобильном), синий акцент с градиентом `#3d6fe0 → #1f3e8c` на
primary-кнопках и FAB, жёлтый `#fff705` строго в двух типах элементов, Montserrat вместо Inter,
скругления 12/16/20, мягкие navy-тени. Добавлена тёмная тема (`prefers-color-scheme: dark`,
navy-поверхности). Логотипа ВШЭ, картинок и блоков сайта нет: в навигации текстовый знак «БК»
и «Бизнес-клуб · Стартапы и вакансии». Логика, API, mock и server не менялись (кроме
UI-кит-правок из «Дополнений координатора», см. ниже).

Сайт сам не открывал (headless Chrome не загрузил его из песочницы) — опирался на таблицу
исследования в задаче.

**axe-core 4.10 (wcag2a + wcag2aa)** в headless Chrome на prod-сборке (`NUXT_MOCK_API=true`):
8 экранов (вход, лента, мои публикации, детали чужой и своей публикации, профиль, отклики
отправленные/полученные) × 375/1280 × светлая/тёмная = 32 прогона — **0 нарушений**
(включая `color-contrast`). Горизонтального скролла нет ни в одном (`scrollWidth ==
innerWidth`), ошибок/предупреждений в консоли нет. Дополнительно проверены 800 и 1024 px —
шапка помещается (ниже 1024 px — компактная: только знак «БК» и кнопка-иконка «+»).

Montserrat реально применяется: `getComputedStyle(body).fontFamily` = `Montserrat, …`,
`document.fonts` — загружены Montserrat 400/500/600/700; `@nuxt/fonts` отдаёт `font-display:
swap` (self-hosted `/_fonts/*.woff2`); `@font-face` лежит в `entry.css`, который SSR-HTML подключает в `<head>`.

### Дополнения координатора

- **Card и gap.** `ui/card` больше не задаёт `display` у корня: классы страниц
  (`listing-body`, `owner-panel`, `my-application-block` — `display:flex; gap`) теперь
  применяются независимо от порядка CSS — зазоры между секциями есть (видно на скриншотах
  `listing-*`). Плюс новый проп `gap: 'sm' | 'md' | 'lg'` (flex-колонка, 8/16/20px) для новых
  мест. Сами три компонента не трогал.
- **Возврат фокуса.** Причина: Safari/iOS WebView (Telegram) не фокусируют кнопку по клику,
  `activeElement` при открытии — `body`. `ui/modal` теперь запоминает последний нажатый
  (`pointerdown`, capture) фокусируемый элемент и возвращает фокус туда, если
  `activeElement` — `body`. Проверено в Chrome (close / Esc / overlay → фокус на
  «Откликнуться» на 375 и 1280) и новым тестом в `tests/ui-modal.test.ts`.
- **ConfirmDialog.** При `tone='danger'` начальный фокус — «Отмена»; при `primary` — как
  раньше, на подтверждении. Тест добавлен.
- **Textarea.** Нативный `maxlength` теперь ставится по умолчанию (`hardLimit` по умолчанию
  `true`; `hardLimit={false}` возвращает прежнее поведение «только счётчик и ошибка»).
  Нюанс: браузер считает UTF-16-единицы, счётчик — code points, так что с эмодзи нативный
  лимит срабатывает чуть раньше счётчика.

## Что не вошло / замечания

- Тёмная тема — только по `prefers-color-scheme`; переключателя и интеграции с темой
  Telegram (`themeParams`) нет.
- `theme-color` в `nuxt.config.ts` (`#ffffff`) не трогал — вне разрешённого блока `fonts`.
  Для мобильного браузера логичнее `#f4f6fb`/`#06081c` по теме — на усмотрение F6.
- `@nuxt/fonts` скачивает Montserrat с Google при сборке (как раньше Inter) — для
  `docker build` нужен интернет.
- Рамка полей ввода (`--color-border-strong` к фону ≈ 1.6:1) не дотягивает до 3:1 по
  WCAG 1.4.11; поля различимы по фону/подписи, axe это не ловит. Если F6 захочет строже —
  поднять `--color-border-strong` до ~`#8f98b3`.
- Новые «до»-скриншоты экранов F4/F5 не снимал — использованы существующие F0/F2.
