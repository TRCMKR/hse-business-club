# Отчёт F3 — Форма публикации и «Мои публикации»

Ветка `task/F3`. Пути ниже — относительно `front/`.

## Что сделано

- `components/listing-form/` — форма создания/редактирования (vee-validate + `listingFormSchema`
  из `utils/validation.ts`), чистый маппинг форма ↔ запрос, общий layout страниц.
- `pages/listings/new.tsx` — создание → `navigateTo('/listings/:id', { replace: true })` + тост
  «Публикация создана». `?kind=vacancy` открывает форму сразу на вакансии (кнопкой «Создать»
  не используется, просто удобство).
- `pages/listings/[id]/edit.tsx` — загрузка (`useAsyncData('listing:<id>')`, тот же ключ, что
  у страницы публикации по соглашению F0), скелетон, предзаполнение, 404 → страница ошибки,
  прочие ошибки → `ErrorState` с «Повторить». Не автор или `closed` → тост «Редактирование
  недоступно» и `replace` на `/listings/:id`. Сохранение → тост «Изменения сохранены» и переход
  на `/listings/:id`.
- `pages/me/listings.tsx` + `components/my-listings/*` — вкладки «Активные N» / «Закрытые N»
  (`Tabs`, `?status=closed`, по умолчанию активные), карточки `ListingCard` со `stats`,
  действия «Отклики» (→ `/listings/:id/applications`), для активных — «Изменить» и «Закрыть»
  (`ConfirmDialog`, tone danger, `loading`); после закрытия карточка без перезапроса переезжает
  во «Закрытые» (счётчики обновляются) + тост. Пусто: «У вас нет публикаций» + CTA «Создать
  публикацию»; пустая вкладка — свой текст (для активных — тоже с CTA). Ошибка — `ErrorState`
  с повтором; загрузка — скелетоны.
- Тесты: 3 файла, 27 тестов (всего в проекте 183).

## Компоненты

### `ListingForm` (`components/listing-form/index.tsx`)

| Prop | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `mode` | `'create' \| 'edit'` | — (обяз.) | `create` — сегмент «Стартап / Вакансия»; `edit` — бейдж вида + «Вид публикации нельзя изменить» |
| `initialValues` | `ListingFormState` | пустой стартап | читается один раз при монтировании (для смены — `key`) |
| `submit` | `(values: ListingFormState) => Promise<void>` | — (обяз.) | отправляет запрос и уходит со страницы; reject → тост + текст под формой |
| `submitText` | `string` | «Опубликовать» / «Сохранить» | |
| `cancelTo` | `string` | — | кнопка «Отмена» (скрыта, если не задан) |

Поведение:
- Поля: «Название», для стартапа — `Select` «Стадия» (обязательна, плейсхолдер «Выберите
  стадию»), «Описание» (счётчик 5000), «Кого ищете» (счётчик 1000), «Теги» (`ChipsInput`,
  ≤ 10, элемент ≤ 40, дубли без учёта регистра не добавляются), для вакансии — «Условия» (≤ 120).
- Ошибки под полями показываются после blur или первой попытки отправки, дальше —
  пересчитываются при вводе (ленивая конфигурация `defineField`).
- При смене вида скрытое поле другого вида откладывается и сбрасывается (стадия →
  `UNSPECIFIED` у вакансии, условия → `''` у стартапа), при возврате — восстанавливается,
  поэтому скрытое поле никогда не блокирует отправку.
- Повторная отправка: пока идёт запрос или после успеха (до ухода со страницы) submit
  игнорируется, кнопка в `loading`. Двойной клик → один запрос (тест + проверка в браузере).
- Несохранённые изменения: `onBeforeRouteLeave` → `ConfirmDialog` «Уйти без сохранения?»
  («Уйти» / «Остаться»), плюс `beforeunload` при закрытии вкладки. После успешной отправки
  охрана отключается.

### `components/listing-form/mapping.ts` (чистые функции)

- `ListingFormState` — `{ kind, title, description, lookingFor, tags, stage, compensation }`.
- `emptyListingForm(kind = STARTUP)`, `fromListing(listing)` (копия тегов; у вакансии стадия
  `UNSPECIFIED`, у стартапа условия `''`), `kindFromQuery(value)`.
- `toUpdateRequest(values): ListingUpdateInput` — trim строк, пустые теги отбрасываются,
  у вакансии `stage = STARTUP_STAGE_UNSPECIFIED`, у стартапа `compensation = ''`.
- `toCreateRequest(values): ListingInput` — то же + `kind`.

### `components/my-listings/`

- `MyListingItem` — props `listing: Listing`, `closing?: boolean` (loading на «Закрыть»);
  emit `close(listing)`; подтверждение — на стороне страницы.
- `MyListingsSkeleton` — prop `count` (3).
- `tabs.ts`: `MyListingsTab = 'active' | 'closed'`, `parseMyListingsTab(query)`,
  `myListingsTabQuery(tab)` (у активной — без `status`), `listingsForTab`,
  `buildMyListingsTabs` (с `count`), `replaceListing(list, updated)` (сохраняет `stats`,
  если в ответе их нет).
- Страница делает один запрос `listMine()` без фильтра и делит по статусу на клиенте: так
  счётчики обеих вкладок верны и закрытая публикация переезжает без перезапроса.

Тесты: схема (стадия обязательна для стартапа и запрещена для вакансии; условия только у
вакансии и ≤ 120; теги ≤ 10, без дублей, элемент 1–40; длины названия/описания/«Кого ищете»
в кодпоинтах), `toCreateRequest`/`toUpdateRequest`/`fromListing`/`kindFromQuery`; компонент
формы (стартап без стадии не отправляется и показывает ошибку; у вакансии нет select стадии;
стадия, выбранная до переключения на вакансию, не мешает и восстанавливается; двойной submit
→ один вызов; серверная ошибка под формой и повторная отправка; режим edit); вкладки
(хелперы, рендер со счётчиками, `?status=closed`, переключение меняет query, пустое
состояние с CTA, ошибка, закрытие через подтверждение → карточка уходит из активных).

Ручная проверка — `NUXT_MOCK_API=true npm run dev -- --port 3103`, headless Chrome через
playwright-core (скрипт во временной папке, в репозиторий не попал), десктоп 1280 и 375 px:

- стартап без стадии: ошибка «Стадия: укажите стадию», POST не уходит;
- «Вакансия»: select стадии исчез, появилось поле «Условия»;
- двойной клик по «Опубликовать» → ровно один `POST /api/v1/listings`, переход на
  `/listings/<id>`, тост «Публикация создана»;
- `/listings/<id>/edit`: поля предзаполнены, бейдж «Стартап»; уход по ссылке «Лента» с
  изменениями → диалог, «Остаться» оставляет на месте; «Сохранить» → `/listings/<id>`, тост,
  `GET /v1/listings/<id>` возвращает новое название;
- «Мои публикации» → «Закрыть» → подтверждение → тост, карточка ушла из активных, на вкладке
  «Закрытые» (`?status=closed`) она есть;
- `/listings/<закрытая>/edit` и `/listings/<чужая>/edit` → редирект на `/listings/<id>` с тостом
  «Редактирование недоступно»;
- 375 px: горизонтального скролла нет, в консоли ошибок нет (кроме «Outdated Optimize Dep»
  при первой загрузке dev).

## Что не сделано / ограничения

- «Изменения видны» проверено через API и «Мои публикации»: страница `/listings/:id` в этой
  ветке ещё заглушка F0 (её делает F2).
- Редирект «Редактирование недоступно» выполняется на клиенте (после гидрации), иначе тост
  терялся бы при SSR-редиректе; до этого SSR отдаёт скелетон формы.
- В тестах компонента формы Vue Router пишет предупреждение «No active route record … 
  onBeforeRouteLeave»: `mountSuspended` монтирует компонент вне `<router-view>`. На поведение
  в приложении не влияет (охрана проверена в браузере).
- Стили `.closed`-карточки, бейджи и `stats` — из `ListingCard` (F0), не менял.
