# I1 — Smoke-тест и сквозная проверка

**Зависимости:** B5, F6, I0. **Блокирует:** I2.
**Читать:** `SPEC.md` §1, §4; отчёты B5, F6, I0 (особенно списки найденных багов).

## Что сделать

1. `scripts/smoke.sh` (bash + curl + jq) против `localhost:8080` с поднятым compose:
   логин Анны → создать стартап → логин Бориса → лента содержит → отклик → повтор = 409 →
   Анна: received содержит, accept → Борис: sent `ACCEPTED`, `GET /v1/listings/{id}`
   содержит `myApplication.status = ACCEPTED` → Борис: загрузить фото (1×1 PNG в base64,
   захардкожен в скрипте) → `avatarUrl` непустой → `curl` по нему → 200 и
   `Content-Type: image/jpeg` (это проверяет реальный MinIO в compose). Любое несовпадение —
   ненулевой код и понятное сообщение. `make smoke` в корневом Makefile.
2. Пройти вручную через фронт (`:3000`) полный сценарий из SPEC §1 на 375px и 1280px,
   плюс: регистрация нового пользователя, редактирование профиля, загрузка/замена/удаление
   фото с телефона (фото с камеры: ориентация, размер), закрытие публикации, отзыв отклика,
   повторный отклик после отзыва, прямые ссылки без cookie.
3. Исправить всё, что сломано на стыке (контракт, CORS, cookie, редиректы, тексты
   ошибок, сид). Правки в `back/`/`front/` — по соглашениям их задач, каждая — в отчёт.
   Баги из отчёта F6 про бэк — закрыть здесь.
4. Проверить наблюдаемость в compose: `make obs` → спан запроса от gateway до SQL в
   Jaeger; в Prometheus есть `grpc_server_handled_total` и `http_request_duration_seconds`.
5. Прогнать `make lint` и `make test` в корне — зелёные.

## Владение

`scripts/**`, `Makefile`; точечные правки в `back/**` и `front/**` с отчётом.

## Дополнения координатора (2026-10-20, из ревью B5)

- `platform/server/gateway.go` `checkEnumNames`: `"stage": null` даёт 400 — `null` у enum-поля
  должен трактоваться как отсутствие (как делает protojson). Исправить + тест.

  должен слать пустые enum-параметры (проверить F1/F3/F4; F6 это тоже видит).
- Сид не атомарен: при падении на середине следующий старт пропустит сид с неполными данными.
  Минимум — описать в README бэка способ восстановления (`make reset`); лучше — откат при
  ошибке (удаление созданных записей) или транзакционный флаг.
- Timestamps приходят с микросекундами (`…28.909982Z`) — проверить, что фронт парсит.
