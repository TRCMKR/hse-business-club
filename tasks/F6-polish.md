# F6 — QA и полировка на живом бэкенде

**Зависимости:** F1–F5 и F7 смержены, B5 готов (живой бэк через `docker compose up db back`
или `make run`). **Блокирует:** I1.
**Читать:** `SPEC.md` §1, §7; отчёты `tasks/reports/F0..F5.md`, `F7.md`, `tasks/reports/B5.md`.

## Что сделать

1. Выключить mock, пройти основной сценарий SPEC §1 на живом бэке на 375px и 1280px.
   Все расхождения контракта (поля, enum, тексты ошибок, коды) — исправить на фронте или
   описать для I1, если это баг бэка.
2. Проверить каждое состояние по чек-листу: загрузка/пусто/ошибка на всех списках; 401
   посреди сессии (удалить cookie в devtools → любое действие → «Сессия истекла» →
   `/login`); 404 по прямым ссылкам; 409 при гонке (два окна, один отклик дважды).
3. Доступность: `:focus-visible`, `aria-label` на иконочных кнопках, диалоги (Esc,
   focus trap), контраст ≥ 4.5:1, `prefers-reduced-motion`. Прогнать axe (через
   `@axe-core/playwright` или devtools) на 5 ключевых страницах, критичные — исправить.
4. Тёмная тема через `prefers-color-scheme` на токенах: проверить все экраны.
5. Производительность SSR: нет двойных запросов (`useAsyncData` ключи), нет `watch`-штормов
   в фильтрах; размер бандла — без лишних зависимостей.
6. Покрытие тестами: добить до наличия тестов у каждого композабла и формы; добавить
   Playwright e2e (`e2e/main-scenario.spec.ts`) основного сценария против mock API
   (`NUXT_MOCK_API=true`) — запускается `npm run e2e`, не в `npm run test`.
7. Скриншоты 375/1280 ключевых экранов в `docs/screenshots/` (для README).
8. Если в `components/ui/avatar` остался `TODO(F7)` (инициалы) — подключить
   `@fe/blob-avatar/vue` по F7 §8, убрать заглушку; проверить, что аватары одинаковы в SSR
   и после гидратации (нет mismatch-warning в консоли).
