     protojson). Реализация — B5 (стык), проверяется e2e.

  10. Коды 501/503 для Unimplemented/Unavailable — допустимы (после B4 Unimplemented нет).
  11. Swagger: `V1UploadAvatarRequest.data` в TS-клиенте типизирован как `Blob`, фактически
      base64-строка — фронт приводит тип в сервисе (F0); контракт не меняем.
- **Документы:** `SPEC.md` §2.4, §4.2; `back/ARCHITECTURE.md` §2, §3, §6; `tasks/I0-compose.md`;

## 2026-10-20 01:58 — отклики: 403 для другой стороны, 404 для постороннего

- **Поднял:** исполнитель B3 (комментарий порта «иначе KindNotFound» противоречил SPEC §2.3).
- **Решение:** SPEC главнее. accept/decline откликнувшимся и withdraw автором → `KindForbidden`
  «Недостаточно прав»; посторонний → `KindNotFound` «Отклик не найден». Права проверяются до
  перехода статуса. Тексты NotFound: «Отклик не найден», «Публикация не найдена», «Участник не
  найден». Неизвестный фильтр статуса → `KindValidation` «Статус отклика: неизвестное значение».
- **Также:** SPEC §3 DDL — убраны FK между схемами, добавлена `listing_author_id` + индекс
  (приведено к ARCHITECTURE §1 п.2–3).
- **Документы:** `back/ARCHITECTURE.md` §2 (комментарии порта applications), `SPEC.md` §2.3, §3.
  Комментарий в `back/internal/applications/applications.go` синхронизирует B5.
- **Уведомлены:** B4 (фейки и тесты BFF должны отражать 403/404), B5 (через задачу: e2e на 403
  для откликнувшегося на accept), B1/B2 — ловушка `DROP SCHEMA` при DB-тестах в нескольких пакетах.
